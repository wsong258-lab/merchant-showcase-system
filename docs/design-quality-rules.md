# Design Quality Rules

## 1. 每次设计前必须先做行业研究

每次新增或优化行业 demo 前，不能直接套固定配色或固定模板。

必须先完成一个简短的行业设计研究步骤。

研究内容包括：

1. 这个行业在中国大陆本地门店场景中的顾客决策逻辑。
2. 目标顾客最关心的信息。
3. 商家最希望顾客完成的动作。
4. 当前流行的页面风格、颜色倾向、排版方式、图片风格。
5. 小红书、抖音、微信、门店二维码等入口下，用户打开页面后的浏览习惯。
6. 同行业常见页面或品牌视觉有什么优点。
7. 同行业常见页面有什么问题，例如信息太乱、按钮不明显、价格不清楚、图片质量差。
8. 这个 demo 应该走“品牌感”“实用转化”“作品展示”“菜单点单”“预约咨询”中的哪一种主路线。

如果当前环境可以联网，应先搜索并参考行业趋势、优秀门店页面、品牌官网、设计案例和移动端落地页。

如果当前环境不能联网，必须基于项目已有文档、参考仓库、现有 demo、行业常识进行分析，并明确说明“未联网搜索”。

## 2. 每次设计前必须先输出设计判断，不要直接写代码

在写代码前，必须先输出设计方案。

设计方案至少包括：

1. 行业定位。
2. 目标顾客是谁。
3. 页面最重要的 3 个转化动作。
4. 页面信息优先级。
5. 视觉关键词。
6. 配色方案。
7. 字体和排版方向。
8. 图片风格。
9. 动效风格。
10. 移动端重点。
11. 第一版不做哪些功能，为什么不做。

只有完成设计判断后，才能开始写代码。

## 3. 配色不能预设死，必须根据研究自己选择

不要在所有行业里套用固定颜色。

每次必须根据行业研究和目标用户自己选择配色。

选择配色时必须说明：

1. 主色是什么。
2. 辅助色是什么。
3. 背景色是什么。
4. CTA 按钮色是什么。
5. 为什么这些颜色适合这个行业。
6. 这些颜色是否适合手机端阅读。
7. 价格、按钮、营业状态、预约入口是否足够明显。
8. 是否避免了廉价感、过度促销感或不符合行业的风格。

不要为了“高级”无理由使用黑金。
不要为了“可爱”无理由使用高饱和粉色。
不要为了“科技感”无理由使用蓝紫渐变。
不要为了“年轻化”导致信息看不清。

配色必须服务于行业、顾客决策和转化目标。

## 4. 必须参考当前流行审美，但不能盲目跟风

每次设计要考虑当前流行的视觉趋势，但不能牺牲可用性。

可以参考：

- 小红书风格的高质量图片排版
- 微信内 H5 的移动端可读性
- 抖音主页承接页的强 CTA
- 现代品牌落地页的留白和卡片结构
- 移动端菜单/预约页的清晰动线
- shadcn/ui、Tailwind、现代 SaaS landing page 的组件质感
- 同行业真实门店的审美偏好

但必须避免：

- 只做视觉，不做转化
- 动效过多导致页面慢
- 文字太小
- 颜色太淡导致按钮不明显
- 图片很漂亮但价格和预约找不到
- 页面像 AI 随机生成
- 页面不像真实商家会使用的东西

## 5. 每次必须先做竞品/参考分析

如果可以联网搜索，必须先搜索 3-5 个同类参考方向。

可以搜索：

- 行业门店官网
- 小程序页面
- 小红书店铺页面
- 抖音团购页
- 美团/大众点评门店页
- 设计灵感站
- 相关 GitHub 前端模板
- 品牌 landing page

研究后总结：

1. 哪些布局值得参考。
2. 哪些颜色值得参考。
3. 哪些功能值得参考。
4. 哪些地方不适合本项目。
5. 本项目应该如何做得更适合中国大陆小门店。

不要复制参考页面代码。
不要照搬品牌视觉。
只学习结构、风格、信息排序和交互模式。

## 6. 每次必须按行业重新决定页面顺序

不要所有行业都使用同一个页面顺序。

必须根据顾客决策路径重新排序。

例如：

美甲美容：
顾客通常先看作品，再看价格，再看预约，再看环境和技师。
因此作品案例和价格必须靠前。

咖啡厅：
顾客通常先看氛围、招牌饮品、地址和营业时间。
因此空间感、菜单、新品和导航要靠前。

奶茶店：
顾客通常先看新品、价格、优惠和点单。
因此菜单、新品、价格和点单入口必须靠前。

街边小店：
顾客通常先看卖什么、多少钱、在哪、怎么联系。
因此菜单、价格、电话、微信、导航必须靠前。

宠物洗护：
顾客通常先看服务、价格、环境安全、案例和预约。
因此环境安全和服务说明必须突出。

每次新增行业 demo，都必须先写出该行业的页面顺序理由。

## 7. 每次必须有明确转化目标

页面不能只是展示。

每个 demo 必须明确核心转化目标。

可选转化目标包括：

- 微信咨询
- 电话联系
- 导航到店
- 提交预约
- 查看作品
- 查看菜单
- 提交点单意向
- 领取优惠
- 加入会员群
- 跳转已有小程序或外卖平台

每个页面最多突出 2-4 个核心动作，不要按钮太多导致混乱。

移动端底部固定操作栏必须根据行业重新设计，不要机械复制。

## 8. 每次开发后必须自我审查

完成代码后，必须进行自我审查。

自查内容包括：

视觉：
- 第一眼是否符合行业气质？
- 是否像真实商家愿意展示的页面？
- 是否有廉价模板感？
- 配色是否合理？
- CTA 是否明显？
- 图片排版是否有质感？
- 是否过度依赖动效？

功能：
- 顾客能否快速知道这家店卖什么？
- 顾客能否快速找到价格、服务或作品？
- 顾客能否快速预约、咨询或导航？
- 页面是否真正帮助商家转化？
- 是否做了第一版不该做的复杂功能？

移动端：
- 是否检查 390px 手机宽度？
- 是否无横向溢出？
- 底部栏是否可用？
- 表单是否易填写？
- 图片是否正常加载？
- 首屏是否清楚？

商业：
- 这个页面是否适合拿给真实商家看？
- 这个页面能否支持销售话术？
- 是否明确流量来自微信、抖音、小红书、地图、二维码等入口？
- 是否避免承诺自动带来流量？

技术：
- 是否运行 npm run build？
- 是否没有修改无关页面？
- 是否没有破坏 /demo/restaurant？
- 数据是否放在 data/demo/[industry].ts？
- 主题是否放在 themes/presets/[industry].ts？
- 是否尽量复用组件？
- 是否避免把行业内容写死在通用组件里？

## 9. 每次汇报必须包含反思结果

完成后不能只说“已完成”。

必须汇报：

1. 研究了什么方向。
2. 如果联网搜索了，说明参考了哪些类型的页面。
3. 如果没有联网，说明基于哪些本地资料判断。
4. 为什么选择这个配色。
5. 为什么这样安排页面顺序。
6. 核心转化动作是什么。
7. 哪些功能没有做，为什么。
8. 移动端检查结果。
9. build 是否通过。
10. 是否影响已有 demo。
11. 访问路径。

## 10. 禁止事项

- 不要所有行业套同一套模板。
- 不要不研究就直接写页面。
- 不要只追求高大上而牺牲转化。
- 不要让顾客滑很久才看到价格、菜单、预约或联系方式。
- 不要在第一版做支付、收银、外卖自动接单、会员充值、复杂库存，除非任务明确要求。
- 不要承诺页面自动带来流量。
- 不要使用过度夸张、医疗化、虚假效果文案。
- 不要复制参考仓库代码。
- 不要直接提交 main。
- 不要影响现有 /demo/restaurant。
